# Hint: Reading an Argument

## Solution

```seq
: arg-empty? ( Int -- Bool )
    args.at string.empty?
;
```

`args.at` consumes the index, pushes the string. `string.empty?`
consumes the string, pushes the Bool. The two stack effects line
up perfectly.

## Why out-of-bounds returns ""

`args.at` is forgiving by design — passing an index past the end
just gives you the empty string instead of crashing. That makes
quick scripts pleasant to write, but it means an empty result is
ambiguous: "the user didn't provide anything" looks the same as
"the user provided an explicitly empty string."

The next exercise builds the bounds-check pattern that lets you
tell the two apart when it matters.
